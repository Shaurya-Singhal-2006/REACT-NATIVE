# Beginner guide to project files

Some project files are not TypeScript source code. JSON files must remain valid JSON, binary image files do not contain readable lines, and the package lock file is generated by npm. Putting ordinary comments into those files would break the app or package installation, so this guide explains their contents in plain language.

## Root configuration files

### `package.json`

- `name`, `version`, and `private` identify this app package and keep it marked as private.
- `main` tells the app to start through Expo Router's entry point.
- `dependencies` lists the packages the running app needs. Expo and React Native provide the app platform; Expo packages add features such as icons, notifications, haptics, clipboard, and routing; AsyncStorage saves data on the phone.
- `devDependencies` lists tools used while writing code. TypeScript checks the types in this project.
- `scripts` gives short names for common terminal commands. `start`, `android`, `ios`, and `web` start Expo for different targets. `lint` runs Expo's lint command. `reset-project` refers to the original starter reset script, which is no longer present in this working tree.

### `package-lock.json`

npm creates this large file to record the exact versions of direct and indirect packages installed. It lets another computer install a matching dependency tree. It is machine-generated data rather than a file to learn React Native from; use `package.json` to see the main dependencies.

### `app.json`

- The `expo` object contains Expo app settings.
- `name`, `slug`, and `version` identify the app in Expo tooling.
- `orientation` requests portrait display, and `icon` points to the main app icon.
- `scheme` defines the app's deep-link prefix; `userInterfaceStyle` allows the operating system's appearance setting.
- `ios.icon` points to the layered icon source in `assets/expo.icon`.
- `android.adaptiveIcon` points to the Android foreground, background, and monochrome icon images. `package` is the Android application ID. `predictiveBackGestureEnabled` is an Android navigation option.
- `web.output` selects static web output, and `web.favicon` selects the browser tab image.
- `plugins` enables Expo Router and configures the splash screen's background and image.
- `experiments` enables typed routes and the React compiler.
- `extra.eas.projectId` connects the app to its EAS project; `owner` names the Expo account.

### `eas.json`

This file defines EAS Build profiles. Both `preview` and `production` set Android `buildType` to `apk`, so both profiles create an installable APK. `preview` is internally distributed. `production` also enables automatic version increments. APKs are for direct installation and testing; use an Android App Bundle (`app-bundle`) for a Google Play Store release.

### `tsconfig.json`

- `extends` starts from Expo's recommended TypeScript settings.
- `compilerOptions.strict` enables stricter type checking to catch more mistakes.
- `paths` creates short import aliases: `@/*` points into `src/`, and `@/assets/*` points into `assets/`.
- `include` tells TypeScript which source and generated type files it should consider.

### `expo-env.d.ts`

This generated TypeScript declaration loads Expo's type definitions. The file itself says it should not be edited and is ignored by Git.

### `.gitignore`

This is a list of files Git should leave out of commits, such as installed packages, Expo build output, local secrets, signing keys, and generated platform folders. Each nonblank pattern names a file or folder to ignore.

### `AGENTS.md` and `CLAUDE.md`

`AGENTS.md` contains the project instruction to read the exact Expo SDK 57 docs before code changes. `CLAUDE.md` points back to that same instruction file.

## Editor settings

- `.vscode/extensions.json` recommends the Expo tools extension for Visual Studio Code.
- `.vscode/settings.json` asks the editor to run code actions such as organizing imports when explicitly requested.
- `.claude/settings.json` enables the listed Claude plugin in Claude Code.

These files use JSON, so explanations belong here instead of as inline comments.

## Image assets

Images referenced by `app.json` are used for the app icon, splash screen, or website favicon. The `assets/expo.icon` folder contains the layered iOS icon design and the images listed in its `icon.json` definition. PNG and SVG files are binary or vector artwork, not source-code lines that can take explanatory comments.

## Folders

- `src/app/` contains Expo Router screens and navigation layouts.
- `src/storage/` contains device storage helpers for meals.
- `src/utils/` contains notification helpers.
- `components/` contains the numbered React Native lessons and reusable dashboard pieces. These files were kept in place.
- `assets/` contains app artwork.
- `node_modules/` contains installed packages and is recreated with `npm install`.
- `.expo/` contains generated local Expo state and cache data; Expo can recreate it.
